- **Report a problem.** A new command, a button in *Settings → Help and feedback*, and a *Report* link on error notices open a problem report you can read and edit: plugin, Obsidian and OS versions, theme, settings (excluded folders only as a count), graph counts (notes, links, roots, multi-parent notes, missing notes, cycles, depth), timings and the last 50 lines of an in-memory log. The vault and home folders are shown as `<vault>` and `~`, and note contents are never included. *Copy* puts it on the clipboard; *Open on GitHub* opens a prefilled issue (a report too long for a link is copied and you paste it). The plugin itself sends nothing.
- **Settings in Obsidian's search.** On Obsidian 1.13 and later the settings tab uses the declarative settings API, so every setting can be found from the settings search. Older Obsidian versions see the same settings as before. Out-of-range values in a hand-edited `data.json` are repaired on load.
- **Keyboard and screen readers.** The drawn tree is one Tab stop: arrow keys move to the nearest note in that direction, Enter opens it, Home returns to the current note, the context-menu key or Shift+F10 opens the menu, `+` / `-` / `0` zoom and fit. Nodes announce their relation (parent, child, ancestor two levels up, missing note, hidden parents). The outline follows the ARIA tree pattern (Up/Down, Right/Left to expand, collapse or go to the parent, Home/End). Toolbar buttons report their pressed state, breadcrumbs work with Enter, focus rings are visible, and faint text and lines got more contrast in both themes.
- **Faster on big vaults.** Editing a note now re-reads only that note's links and redraws nothing unless they changed (before, every edit rebuilt the whole graph and redrew every open tree). Sorting no longer builds a collator per comparison, layers are sized in one pass, edges are drawn as two paths, nodes of trees with more than 800 notes are created as they scroll into view, and outlines with more than 1,500 rows start with deep branches collapsed. On a generated 20,000-note vault the whole-vault layout went from 1.2 s to under 0.1 s; numbers are in the README and `npm run bench` reproduces them.
- **Beta channel.** Versions like `0.3.1-beta.1` are published as GitHub pre-releases that [BRAT](https://github.com/TfTHacker/obsidian42-brat) can install, without reaching the community store; `manifest-beta.json` tracks the newest beta. See *Beta versions* in the README.
- **Feedback, once.** After a week of use the tree view asks once, in a small box, what you use the plugin for. *Tell me on GitHub* opens a prefilled issue in your browser; *Not now* asks again much later; *Don't ask again* is final. No network calls.
- **Fix:** a plain click on a node in the drawn tree could be swallowed by the canvas (it captured the pointer on every press, which retargets the click), so the note did not open. The canvas now only captures the pointer once you actually drag. Found by the new end-to-end tests.
- A failure while drawing a tree, writing a note or opening one now shows a message with a way to report it instead of failing silently.

**Tested:** 87 unit and DOM tests (vitest + jsdom), including the report and redaction functions, incremental graph updates, cycle detection on a 20,000-note chain, and keyboard navigation in the tree and outline; type-check, lint with 0 warnings, production build. New end-to-end tests drive a real Obsidian (oldest supported and latest) through the tree view, the family/phylogenetic switch, clicking and keyboard-opening nodes, the code block, the settings tab and the report; they run in GitHub Actions on Linux.

**Not verified by hand in Obsidian:** screen-reader announcements (NVDA/VoiceOver), how the declarative settings look on 1.13+, and drawing speed on a real 20,000-note vault (the drawing timings above come from jsdom). The demo GIF in the README is still a placeholder.
